# 经销商团队健康度 AI 诊断 MVP

> 状态：MVP 原型。当前使用规则模型和合成 Mock Data，用于验证信息架构、诊断流程与可解释性，不代表真实业务预测结果。

## 要解决的问题

传统经营看板通常要求运营人员自己翻指标、找异常和拼接结论。这个 MVP 将入口改为团队经营诊断，帮助运营团队先理解整体经营状态，再筛出重点团队，依次核查健康度、失分来源和风险名单。

## 目标用户

- 全国或区域经销商运营负责人；
- 负责多个经销商团队的业务运营人员；
- 需要复盘团队结构、活跃与新人发展的管理者。

## 核心流程

```text
总体经营概览
  → 团队分层与标签分布
  → Top / Bottom 排行
  → 重点关注团队
  → 单团队健康度诊断
  → 失分归因
  → 风险类型与名单核查
```

## MVP 范围

已实现：

- 全体团队总体目标达成率、活跃率和平均健康度；
- 团队分层、风险标签分布、Top 10 与 Bottom 10；
- 团队健康度评分及六维得分解释；
- 按加权失分排序的归因分析；
- 人员流失、新人招募不足、行动不足、临期目标不足和团队结构五类风险提示；
- 重点团队与风险成员名单的交互式 Mock Data 演示。

本版本不包含：

- 个体经销商健康度评分；
- 自动生成行动计划或替代运营人员做决定；
- 机器学习预测、经过校准的置信度或真实业务效果证明；
- 真实业务数据接入、权限和审计功能。

## 健康度规则模型

| 维度 | 权重 | 当前输入示例 |
|---|---:|---|
| 团队销售表现 | 25% | 目标达成、周期剩余时间 |
| 团队活跃结构 | 20% | 活跃率、活跃下降 |
| 顾客资产质量 | 20% | 活跃、复购、订阅和流失综合分 |
| 新人启动质量 | 15% | 招募完成、新人启动率 |
| 业绩集中风险 | 10% | Top 3 贡献、中腰部贡献 |
| 工具 / 行动能力 | 10% | 工具、培训、活动等经营动作 |

总分计算：`团队健康度 = Σ（维度得分 × 维度权重）`。当前阈值是用于产品讨论的 V0.1 规则，不是经过统计验证的行业标准。

## 运行 Demo

直接用浏览器打开 [`demo/index.html`](demo/index.html)。该页面不需要安装依赖或启动服务。

运行冒烟测试需要 Node.js：

```bash
node tests/smoke-test.js
```

## 数据与隐私

Demo 内的 12 个团队、成员姓名、指标和证据均为合成数据，不对应真实个人或真实经营主体。原始业务 PRD、真实经销商数据和个人信息未提交到本仓库。

## 已知限制

- 权重、阈值和扣分公式尚未用历史业务数据回测；
- Mock 样本只有 12 个团队，Top 10 与 Bottom 10 存在重叠；
- 当前风险提示依赖静态规则和预设证据，不等于人员流失预测；
- 分层是互斥主分群，标签可叠加，两者不能混为同一统计口径；
- 项目尚未完成真实运营用户的可用性与增量价值验证。
