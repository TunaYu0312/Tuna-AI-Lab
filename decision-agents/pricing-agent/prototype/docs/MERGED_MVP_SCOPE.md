# 菜单定价决策会议工作台：合并开发基线

> 产品名：Menu Pricing Decision Room  
> 合并来源：`菜单定价与 Product Mix 决策会议 Agent MVP PRD V1.1` + `菜单定价决策会议工作台 MVP PRD V1.0`  
> 开发目标：用一个模拟套餐调价案例，完整演示从问题定义到决策冻结的可追溯闭环。

## 1. 合并后的产品定位

产品首先是**定价决策会议工作台**，不是 BI 看板或自动定价器；P-mix、Menu Grid、运营情景与竞品分析是会议按需调用的可靠工具，而不是独立堆叠的报表。

MVP只处理：一场会议、一个套餐价格决策、一个试点与复盘闭环。

## 2. 两份 PRD 的取舍

| 主题 | 合并结论 | MVP实现 |
|---|---|---|
| 主产品结构 | 采用五阶段会议工作台 | 当前决策、共同事实、方案与权衡、问题与证据、决策与复盘 |
| P-mix | 作为方案比较的确定性计算层 | ADTC、UPH、ADQ、AC、ADS、GP/TC、ADGP联动 |
| Menu Grid | 用于商品角色定位，不自动给出调价结论 | UPH × Unit GP；GP Rate为辅助证据；展示情景角色迁移 |
| 商圈与顾客 | 全国平均值不得直接替代分层结论 | 商务办公、交通枢纽、社区的弹性、产能与价值风险矩阵 |
| 门店运营 | 从普通权衡项提升为硬性可行性闸门 | 人工、瓶颈工位、出餐、报废与机会成本进入净增量贡献 |
| 证据治理 | 事实、估算、假设与未知分层 | 来源、口径、时间范围、Evidence Grade和证据队列 |
| Agent | 一个Agent、五种工作模式 | 结构化观点、调用预设分析、更新方案、生成纪要；不自动改价 |
| 试点 | 低证据决策必须通过试点学习 | 试点店/对照店、扩大条件、暂停线、48小时回滚和复盘日期 |

## 3. 核心计算口径

```text
ADQ_i = ADTC × UPH_i / 100
AC = Σ(UPH_i / 100 × Net Unit Revenue_i)
ADS = ADTC × AC
GP per TC = Σ[UPH_i / 100 × (Net Unit Revenue_i − Unit Product Cost_i)]
ADGP = ADTC × GP per TC
```

目标商品的价格或UPH变化不能孤立计算。每个方案同时检查Traffic、Own-item、Substitution和Basket Effect。缺失参数保留为假设或未知，不能静默设为零。

## 4. MVP页面与会议产出

1. **当前决策**：确认首要目标、六类范围、Decision Owner、成功标准和Guardrails。
2. **共同事实**：确认5—8条关键事实、商圈差异、口径、来源与证据缺口。
3. **方案与权衡**：比较维持现状、统一调价、分商圈、套餐重构和小范围试点；运行净增量贡献及P-mix情景。
4. **问题与证据**：把现场观点转为事实、假设、约束、风险或分析任务，并将结果回写方案。
5. **决策与复盘**：在批准、有条件批准、试点、延期、否决中选择；冻结理由、异议、Owner、监测、停止线和复盘日。

## 5. 原型贯穿案例

是否将A套餐从28元调整至30元，先在商务办公和交通枢纽商圈的30家门店开展6周试点，以提升门店净增量贡献，同时确保核心会员复购、P90出餐、报废与投诉不突破阈值；社区门店维持现价并作为对照。

## 6. MVP验收标准

- 3分钟内可理解需要决定什么、谁决定、何时决定；
- 五阶段可顺序切换，每阶段有明确问题和产出；
- 调整ADTC、目标UPH和净单价后，ADQ、AC、ADS、GP/TC、ADGP同步重算；
- Menu Grid使用UPH × Unit GP并展示商品角色与目标套餐迁移；
- 商圈差异、顾客价值、门店运营和财务结果使用同一方案基线；
- 现场观点能进入证据队列，预设分析结果能回写方案；
- 决策必须包含Owner、截止日期、监测阈值、扩大/暂停/回滚条件和复盘日；
- 决策可冻结为正式版本并导出Markdown纪要；
- 所有演示数字明确标记为模拟数据，AI不执行真实改价。

## 7. 明确不纳入本轮

- 完整供应链智能备货与物流库存优化；
- 机器学习价格弹性模型与自动最优价格推荐；
- 一店一价和生产环境自动改价；
- 真实POS、KDS、财务和竞品数据接入；
- 多决策项目组合管理、复杂审批和企业级权限；
- AI替代CEO、COO或经营委员会作最终决定。

## 8. 下一阶段接口边界

原型验证通过后，优先拆出四个可测试服务：Metric & Data Quality、Scenario Calculation、Constraint/CDC、Meeting Workflow。真实数据接入应先完成一次历史会议回放和口径冻结，再进入生产化评估。
