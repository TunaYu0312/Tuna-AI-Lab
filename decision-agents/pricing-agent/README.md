# Pricing Agent / Menu Pricing Decision Room

面向连锁餐饮企业的菜单定价决策会议助手。它不是自动定价器，也不只是会议纪要工具，而是把共同事实、方案比较、经营约束、试点验证和正式复盘组织成一条可追溯的决策链。

## 当前原型覆盖

1. 当前决策：冻结目标、范围、决策人和成功条件。
2. 共同事实：区分事实、估算、假设及证据缺口。
3. 方案与权衡：先经过销售额硬约束，再比较整体菜单经济结果。
4. 问题与证据：把现场观点转成可验证的分析任务。
5. 决策与复盘：记录策略、试点路线、停止线、责任人与复盘日期。

## 核心计算链

```text
价格调整 → 目标产品 UPH 变化
目标产品 ADQ = UPH × 同季 ADTC
UPH 迁移 → Product Mix 变化
Product Mix → 整体菜单销售额、毛利额、毛利率与净增量贡献
```

价格不被设定为 ADTC 的直接原因。ADTC 作为季节、商圈和星期结构共同形成的交易量基线，同时进入无调价基准与调价方案，避免把客流季节性误归因于价格。

## 数据边界

原型中的经营数字和产品迁移参数均为演示数据。正式使用前，需要接入企业经审核的 POS、成本、会员、KDS 和历史调价事件数据，并由分析师校准自价格响应、替代回收率和产品间迁移权重。AI 可以提出参数建议，但不能绕过人工确认或直接执行改价。
